# Field Patterns from Production Flutter Apps

These patterns were learned from real shipped GetX + REST + Firebase apps. They are good defaults when a project has no convention of its own. When a project already does something differently, the project wins. Each pattern lists *why* it exists, because the reasoning is what transfers.

## Project shape (feature-first GetX)

```text
lib/
  main.dart                     # guarded init, then runApp
  firebase_options.dart         # generated by flutterfire configure
  route/route.dart              # GetPage list + route name constants
  core/
    auth/                       # auth gate, session bootstrap
    const/                      # app colours, theme pieces, asset paths
    global_widgets/             # buttons, fields, banners, placeholders
    network_caller/             # api_client.dart, endpoints.dart, connectivity_service.dart
    observability/              # crash_reporter, performance_monitor, analytics/replay
    service_class/              # device token, location, notifications, local storage
    text_style/                 # text-style helper functions
    update/                     # in-app update check (decision / service / prompt)
    util/                       # validators, formatters, error mappers
  feature/<name>/
    controller/<name>_controller.dart
    model/<name>_model.dart
    service/<name>_api.dart     # only when the feature has several endpoints
    view/<name>_view.dart
    view/widget/                # feature-private widgets, <name>_colors.dart tokens
```

## Startup that can't brick the app

```dart
void main() async {
  WidgetsFlutterBinding.ensureInitialized();
  var firebaseReady = false;
  try {
    await Firebase.initializeApp(options: DefaultFirebaseOptions.currentPlatform);
    firebaseReady = true;
  } catch (e) {
    debugPrint('Firebase init failed, continuing without it: $e');
  }
  await CrashReporter.init(firebaseReady: firebaseReady);
  runApp(const MyApp());
  WidgetsBinding.instance.addPostFrameCallback((_) {
    NotificationRouter.flushPending(); // replay a tap that launched the app
  });
}
```
**Why:** on iOS, Firebase or push setup can fail before APNs is configured. Optional services must degrade, never block launch. Pass `firebaseReady` down, so there's one source of truth.

## One static API client

- `ApiClient.get/post/patch/put/delete(path, {body, auth = true})`, plus `multipart` and an SSE `postStream` when needed.
- Base URL from `String.fromEnvironment('API_BASE_URL', defaultValue: ...)` so dev builds can point at `10.0.2.2` (the Android emulator's view of the host).
- JSON encode/decode in one place. Inject `Authorization: Bearer` from the session store. Use a single timeout constant.
- **`ApiException(statusCode, detail)`** for any non-2xx (FastAPI-style `{"detail": ...}`). **`NetworkException extends ApiException`** for no connection or timeout. Because it extends the type every controller already catches, users get an honest "check your connection" message without touching every controller.
- **401 → refresh → replay once** (`isRetry` flag). Treat *refresh rejected* (session over → sign out) differently from *refresh unreachable* (network blip → keep the session, show an error). Signing someone out over one dropped packet is a classic bug.
- Invalidate related caches after successful mutations.
- Breadcrumb method/path/status to crash reporting. Never send bodies or tokens.

## Controllers
- `GetxController` with `.obs` fields, `onInit()` kicks off `fetch()`, and `try/catch/finally` sets `loading`.
- Branch on `ApiException` to show `e.detail`, with a generic fallback for anything else.
- Parse defensively: `final raw = data is Map ? data['orders'] : null; if (raw is! List) return;` plus `Model.fromJson` that returns `null` for bad rows (skip them rather than crash).
- Keep presentation helpers (date labels, name lookups) on the controller or in `util/` as pure static functions, so they're testable.

Watch out (common in this style, raise but don't silently refactor):
- `Get.put(Controller())` inside `build()`. It works, but it hides lifetime. Prefer bindings, or `Get.put` in a route/page factory, for new code if the user agrees.
- Cross-feature `Get.find<OtherController>()`. Guard with `Get.isRegistered` when the other feature may not be loaded.
- Tokens in `SharedPreferences`. Recommend `flutter_secure_storage` for refresh tokens.

## Views
- `StatelessWidget` + `Obx` scoped to the part that changes.
- Order of states: loading with no data → empty → data with `RefreshIndicator(onRefresh: c.fetch)`.
- Per-screen colour token classes (`MenuColors.bg`, `.card`, `.title`, `.muted`, `.accent`) and text-style helpers (`sfProTextStyle(...)`, `globalTextStyle(...)`) instead of inline styles.
- Private sub-widgets (`_SectionHeader`, `_OrderCard`) in the same file when only used there, and `view/widget/` when shared within the feature.
- Global overlays (offline banner) go in `GetMaterialApp.builder` as a `Stack`, so the app keeps its full height and loaded data stays usable offline.
- Haptics through one helper (`AppHaptics`), so they can be tuned or disabled centrally.

## Observability
- A crash reporter that is **fail-safe by construction**: every entry point swallows its own errors and is a no-op until init succeeds.
- Fatal = uncaught async (`PlatformDispatcher.onError`) and isolate errors. Non-fatal = `FlutterError.onError` and explicit `recordError` (e.g. 5xx). Mixing them ruins the crash-free rate.
- Disabled in debug builds.
- **Never** log request/response bodies, tokens, emails, phones or addresses. Log paths, status codes and ids only.
- Manual HTTP traces for Firebase Performance, because Dart's `HttpClient` isn't auto-instrumented.
- A crash test only behind `--dart-define=CRASH_TEST=true`.

## In-app update gate
Split into a **pure decision function** (`none / prompt / block`), a service (HTTP check-in), and a prompt widget. **Every failure resolves to `none`.** A wrongly-blocked user can't open the app to receive the fix, so the gate must fail open.

## Push notifications
- A router that **parks** a notification tapped while the app was terminated, then replays it after the first frame, when a navigator exists.
- Device-token registration as its own service, re-sent on token refresh and after login.

## Multi-role apps (admin/user, staff/participant)
- Seen as `feature/users/admin_site/…` + `client_site/…`, or one bottom-nav feature per role.
- Route by role in **one place** (a role router/auth gate), not duplicated across splash and login. Unknown role → sign-out with a message, never a blank screen.
- Share models, API client and widgets across roles. Duplicated per-role copies (e.g. two near-identical "suggested friends" sections) drift apart. Extract a shared widget with role-specific parameters.
- The backend enforces role permissions. Hiding admin screens in the app is UX, not security.

## Auth UX
- OTP inputs with SMS autofill (`smart_auth` / platform SMS retriever) and a resend cooldown.
- An auth-required bottom sheet for guest users who hit a gated action, instead of hard redirects.
- Store absolute token expiry (`now + expires_in`) so the app can refresh *before* a call fails. Also read the JWT `exp` claim as a fallback for older sessions.
